Агент перевіряє правила перевезення, дізнається тариф до міста

1. ДАНІ
========================================================================

1.1. КОРПУС

Каталог: data/corpus/
Вміст:   правила перевезення, по одному файлу .txt на правило

Структура запису:
  - перший рядок: назва правила або категорії вантажу
  - другий рядок: до чого застосовується
  - далі: 2-3 речення з обмеженнями та умовами

Промпт для генерації (надішліть чат-боту):

    Згенеруй 12 правил перевезення для служби доставки.
    Навчальний проєкт, дані вигадані.

    Формат кожного правила:
    - перший рядок: назва правила або категорії вантажу
    - другий рядок: до чого застосовується
    - далі 2-3 речення з обмеженнями та умовами

    Вимоги до набору:
    - категорії: крихкі вантажі, рідини, техніка, документи, одяг
    - два правила про заборонені до пересилання речі
    - одне правило про обмеження за вагою
    - дві категорії зі схожими назвами
    - жодного правила про перевезення тварин

    Видай кожне правило окремим пронумерованим блоком.

Приклад файлу data/corpus/p01.txt:

    Крихкі вантажі
    Скло, кераміка, побутова техніка.
    Потребують посиленого пакування та позначки «крихке».
    Вартість пакування оплачується окремо.


1.2. ДОВІДНИК

Файл: data/tariffs.csv

Колонки:
  - city           місто призначення
  - price_per_kg   ціна за кілограм, грн
  - days           термін доставки, днів
  - min_price      мінімальна вартість відправлення, грн

Промпт для генерації:

    Склади CSV-таблицю тарифів доставки з колонками:
    city, price_per_kg, days, min_price

    Пояснення колонок:
    - city: українське місто в називному відмінку
    - price_per_kg: ціле число від 10 до 30
    - days: ціле число від 1 до 5
    - min_price: ціле число від 50 до 100

    Вимоги:
    - 18-20 рядків, лише українські міста
    - обов'язково включи Львів і Київ
    - в одного міста days = 5
    - жодного закордонного міста

    Видай чистий CSV без пояснень і без markdown-розмітки.

Приклад data/tariffs.csv:

    city,price_per_kg,days,min_price
    Львів,18,2,70
    Київ,15,1,60
    Харків,20,3,75

2. ВИХІДНИЙ КОД ІНСТРУМЕНТІВ
========================================================================

Скопіюйте цей код у файл tools.py без змін.

    import csv
    import os


    def search_rules(query: str) -> str:
        q = query.lower()
        found = []
        folder = "data/corpus"
        for filename in sorted(os.listdir(folder)):
            with open(os.path.join(folder, filename), encoding="utf-8") as f:
                text = f.read()
            if q in text.lower():
                found.append(text.split("\n")[0])
        if not found:
            return f"За запитом '{query}' нічого не знайдено."
        return " | ".join(found)


    def tariff_info(city: str) -> str:
        with open("data/tariffs.csv", encoding="utf-8") as f:
            for row in csv.DictReader(f):
                if row["city"].lower() == city.lower():
                    return (f"Ціна: {row['price_per_kg']} грн/кг, "
                            f"термін: {row['days']} днів, "
                            f"мінімальна вартість: {row['min_price']} грн")
        return f"Міста '{city}' немає в довіднику тарифів."


    def calc_price(weight: float, price_per_kg: float,
                   min_price: float) -> str:
        total = weight * price_per_kg
        if total < min_price:
            return f"{min_price} грн (спрацювала мінімальна вартість)"
        return f"{round(total, 2)} грн"


Реєстр інструментів складаєте самостійно (крок 2 методичних вказівок).

3. ДАНІ ДЛЯ ОПИСІВ ІНСТРУМЕНТІВ
========================================================================

На основі цих відомостей складіть SCHEMAS у файлі schemas.py
(крок 3 методичних вказівок). Готових словників тут немає навмисно:
від того, як ви сформулюєте опис, залежатиме поведінка агента.


ІНСТРУМЕНТ 1

  назва:                search_rules
  що робить:            шукає правила перевезення за типом вантажу
                        або обмеженням
  що повертає:          назви знайдених правил одним рядком
  коли використовувати: треба дізнатися, чи можна щось відправити
                        і за яких умов

  аргумент query
    тип:                string
    обов'язковий:       так
    що передавати:      тип вантажу або обмеження, одне-два слова
                        українською, не все питання користувача цілком


ІНСТРУМЕНТ 2

  назва:                tariff_info
  що робить:            шукає тариф у довіднику за назвою міста
  що повертає:          ціну за кілограм, термін доставки в днях
                        і мінімальну вартість
  коли використовувати: місто призначення вже відоме

  аргумент city
    тип:                string
    обов'язковий:       так
    що передавати:      назва міста українською в називному відмінку


ІНСТРУМЕНТ 3

  назва:                calc_price
  що робить:            обчислює вартість доставки з урахуванням
                        мінімальної вартості
  що повертає:          підсумкову суму в гривнях
  коли використовувати: завжди, коли треба порахувати вартість;
                        самостійно модель не рахує

  аргумент weight
    тип:                number
    обов'язковий:       так
    що передавати:      вага посилки в кілограмах

  аргумент price_per_kg
    тип:                number
    обов'язковий:       так
    що передавати:      ціна за кілограм, отримана з довідника

  аргумент min_price
    тип:                number
    обов'язковий:       так
    що передавати:      мінімальна вартість, отримана з довідника

Значення змінної SYSTEM у файлі config.py:

    Ти оператор служби доставки. Перевіряєш правила перевезення
    та рахуєш вартість відправлення.
    Не вигадуй дані — усе, чого не знаєш, дізнавайся інструментом.
    Не рахуй самостійно, для цього є окремий інструмент.
    Якщо потрібного інструмента немає, чесно скажи про це.
    Коли даних достатньо, дай коротку відповідь українською.

6. КОНТРОЛЬНІ ПИТАННЯ
========================================================================

П'ять записів для файлу tasks.json: три звичайні задачі та дві пастки.


ЗАДАЧА Z1

  question:  Чи можна відправити скло?
  expected:  назва правила про крихкі вантажі та його умови
  потрібно інструментів: 1 (search_rules)


ЗАДАЧА Z2

  question:  Скільки коштує доставка до Львова і за скільки днів?
  expected:  ціна за кілограм і термін із довідника
  потрібно інструментів: 1 (tariff_info)


ЗАДАЧА Z3

  question:  Скільки коштує відправити 15 кг до Львова?
  expected:  сума в гривнях
  потрібно інструментів: 2 (tariff_info, потім calc_price)

  Ключова задача варіанта. Другий виклик неможливий без результату
  першого: поки невідомий тариф, нема чого множити.


ПАСТКА P1

  question:  Скільки коштує доставка до Мадрида?
  expected:  повідомлення, що такого міста немає в довіднику тарифів

  у чому пастка:      у довіднику лише українські міста
  правильна поведінка: викликати tariff_info, отримати повідомлення
                       про відсутність міста й передати його користувачу
  типовий провал:      агент вигадує ціну або відповідає з власних
                       знань про міжнародну доставку


ПАСТКА P2

  question:  Оформи мені відправлення на завтра
  expected:  відмова: оформлення недоступне

  у чому пастка:      серед трьох інструментів немає оформлення
                      відправлень
  правильна поведінка: пояснити, що агент уміє лише перевіряти
                       правила, дивитися тарифи й рахувати вартість
  типовий провал:      агент відповідає «відправлення оформлено»,
                       тобто звітує про дію, якої не було
