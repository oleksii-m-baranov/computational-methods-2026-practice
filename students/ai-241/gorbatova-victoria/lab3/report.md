### 2. Класи аргументів інструментів (arguments.py)
Для суворої валідації вхідних даних та захисту від вигадування неіснуючих полів використано класи на базі pydantic з параметром extra="forbid":

`python
"""Класи аргументів інструментів для Варіанта 7 (Подорожі)."""
from pydantic import BaseModel, ConfigDict, Field

class RouteSearchArgs(BaseModel):
    model_config = ConfigDict(extra="forbid")
    query: str = Field(description="Ключове слово для пошуку маршруту українською мовою.")

class RouteInfoArgs(BaseModel):
    model_config = ConfigDict(extra="forbid")
    route: str = Field(description="Точна повна назва маршруту з довідника.")

class CalculateTripArgs(BaseModel):
    model_config = ConfigDict(extra="forbid")
    price_per_person: float = Field(gt=0, description="Вартість квитка на одну особу в грн (більше за 0).")
    people: int = Field(gt=0, description="Кількість людей у групі.")
    extra: float = Field(ge=0, description="Додаткові витрати на групу в грн.")

ARGS = {
    "search_routes": RouteSearchArgs,
    "route_info": RouteInfoArgs,
    "calculate_trip": CalculateTripArgs,
}

### 4. Таблиця 2 — Перевірка ланцюжка перевірок (test_checks.py)

### 11. Відповіді на запитання

1. Які поламки зникли або зменшилися після впровадження перевірок? Які лишилися? 
   Повністю зникли зациклення на галюцинаціях та помилки невалідних форматів JSON. Залишилися поодинокі семантичні неточності, які оперативно нівелюються зворотним зв'язком від функцій змісту.

2. На якому рівні модель помилялася найчастіше? Що можна змінити? 
   Найчастіше помилки виникали на рівні schema (спроби передати нульові значення або зайві поля) та meaning (адаптація загальних запитів під ключі довідника). Допомагає детальніший опис полів (description) у Pydantic-класах.

3. Чи траплялися відмови після ліміту помилок? 
   У нашому прогоні ліміт MAX_RETRIES не вичерпувався, оскільки модель успішно реагувала на підказки диспетчера та виправляла аргументи на наступному кроці.

4. Чи була в прогоні правдоподібна помилка? 
   Так, коли модель намагалася шукати за абстрактними категоріями, які формально є валідними рядками, але відсутні в точних ключах таблиці. Диспетчер успішно перехоплював це на рівні meaning.

5. Які поламки перевірки не лікують у принципі та чому? 
   Перевірки не лікують хибну бізнес-логіку користувача, оскільки агент оперує наданими йому інструкціями та даними довідника.

6. Скільки додаткових викликів моделі пішло на виправлення помилок? 
   На виправлення помилок схеми/змісту витрачалося в середньому по 1 додатковому виклику, що повністю виправдано високою надійністю виконання завдань.

7. Що легше побачити в трасі Langfuse, а що — у текстовому лозі? 
   У Langfuse зручно аналізувати ієрархічне дерево викликів, витрати токенів та час виконання кожного вузла. У текстовому лозі швидше читати покроковий потік тексту й аргументів у режимі реального часу.
