## 2. Класи аргументів інструментів

Для суворої валідації вхідних даних моделі та автоматичної генерації JSON-схем створено класи на базі `pydantic.BaseModel` із забороною додаткових вигаданих полів (`extra="forbid"`).

Файл `arguments.py`:

```python
"""Класи аргументів інструментів (Варіант 1 — Бібліотека)."""
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field


class SearchBooks(BaseModel):
    model_config = ConfigDict(extra="forbid")
    query: str = Field(
        description="Жанр, тема або рівень складності, одне-два слова українською, не все питання користувача цілком."
    )


class BookInfo(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(
        description="Точна назва книжки, як вона записана в каталозі."
    )


class Calculate(BaseModel):
    model_config = ConfigDict(extra="forbid")
    operation: Literal["mul", "add", "sub"] = Field(
        description="Операція: mul — множення, add — додавання, sub — віднімання."
    )
    a: float = Field(ge=0, le=10000, description="Перший операнд (невід'ємне число).")
    b: float = Field(ge=0, le=10000, description="Другий операнд (невід'ємне число).")


class IssueBook(BaseModel):
    model_config = ConfigDict(extra="forbid")
    title: str = Field(description="Назва книжки для видачі.")


ARGS = {
    "search_books": SearchBooks,
    "book_info": BookInfo,
    "calculate": Calculate,
    "issue_book": IssueBook,
}
```

## 6. Аналіз трас у Langfuse

### Структура події в дереві траси
Кожен крок взаємодії з моделлю та інструментами в Langfuse чітко розбивається на п'ять складових:
1. **Крок:** вузол виклику моделі `generation` (наприклад, `qwen2.5:3b` у дереві траси `checks-Z3`).
2. **Вхід:** вхідний масив `messages` із системним промптом, питанням користувача та історією попередніх кроків.
3. **Рішення:** згенерована моделлю відповідь із викликом функції `tool_calls` (наприклад, `book_info(title="Про алгоритми")`).
4. **Дія:** дочірній вузол виконання інструмента `@observe(name="call_tool")` з аргументами виклику.
5. **Результат:** вихідний статус `(level, message)` — повернення помилки рівня `meaning` або `ok` зі значенням із бази даних.

## 8. Додаткове завдання: запобігання помилкам на сервері (Structured Outputs)

Реалізовано скрипт `structured_demo.py` з використанням параметра `response_format={"type": "json_schema"}`.

* **Результати тестування:**  
  При передачі Pydantic-схеми сервер примусово обмежує простір вибору токенів, гарантуючи, що модель видає валідний JSON строго за схемою (без кодових блоків markdown, без зайвих пояснень і без вигаданих ключів).
* **Чи можна прибрати перевірки в коді?**  
  Ні, прибирати перевірки в коді не можна з двох причин:
  1. Structured Outputs гарантує лише синтаксис та схему (`syntax`, `schema`), але не контролює рівень змісту (`meaning`): сервер не може знати, чи існує книга в базі даних CSV або чи не вийде від'ємне число при відніманні.
  2. Не всі сервери інференсу або квантовані локальні рушії підтримують граматики BNF та JSON-схеми в повному обсязі.

3. Підключення **Langfuse** забезпечило наочну спостережуваність (observability) затримки, витрат токенів та ієрархії викликів інструментів.
