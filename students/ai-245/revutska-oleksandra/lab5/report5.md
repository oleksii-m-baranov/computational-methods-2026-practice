# Лабораторна робота №5

**Тема:** Розробка локального RAG-асистента бібліотеки та дослідження ефективності пошуку

**Виконала:** Ревуцька Олександра  
**Група:** AI-245

---

## 1. Мета роботи

Розробити локального бібліотечного асистента з використанням технології Retrieval-Augmented Generation (RAG).

Дослідити вплив різних способів поділу документів на фрагменти (chunking) на якість пошуку, порівняти три варіанти опису інструмента `search_docs` та оцінити якість відповідей асистента.

## 2. Використані технології

У роботі використано:

- **Python** — реалізація програмної логіки.
- **Ollama** — локальний запуск мовної моделі.
- **qwen25-4k** — генерація відповідей.
- **bge-m3** — побудова векторних представлень тексту.
- **FAISS** — векторний пошук документів.
- **RAG** — генерація відповідей із використанням знайденого контексту.

## 3. Теоретичні відомості

RAG (Retrieval-Augmented Generation) — технологія, яка поєднує пошук інформації у зовнішніх джерелах із генерацією відповіді мовною моделлю.

Основні етапи роботи RAG:

1. Завантаження документів.
2. Поділ документів на фрагменти.
3. Створення ембедингів.
4. Побудова векторного індексу.
5. Пошук релевантних фрагментів.
6. Формування відповіді з використанням знайденої інформації.

Такий підхід дозволяє асистенту використовувати локальну базу знань замість того, щоб покладатися лише на знання мовної моделі.

## 4. Хід виконання роботи

### 4.1. Підготовка документів

Для експериментів сформовано набір із **17 текстових документів** бібліотеки.

Документи розміщено у двох каталогах:

- `data/corpus/` — 12 текстових файлів;
- `data/docs/` — 5 текстових файлів.

Документи використовуються як джерело інформації для відповідей асистента.

### 4.2. Реалізація chunking

У файлі `chunking.py` реалізовано поділ документів на текстові фрагменти.

Перевірено шість конфігурацій поділу тексту, зокрема поділ за абзацами та поділ на фрагменти фіксованого розміру.

Для основної конфігурації використано:

- Метод: `paragraphs_800`
- Кількість фрагментів: **39**
- Параметр `TOP_K`: **3**

### 4.3. Створення векторного індексу

Для створення ембедингів використано модель `bge-m3`.

Пошуковий індекс реалізовано за допомогою FAISS із використанням `IndexFlatIP`.

Побудова індексу виконується командою:

```cmd
python build_index.py
```

Після виконання створюються файли:

- `index/docs.faiss` — векторний індекс;
- `index/chunks.json` — інформація про текстові фрагменти.

### 4.4. Реалізація RAG-пошуку

У файлі `rag.py` реалізовано пошук релевантних фрагментів.

Алгоритм роботи:

1. Отримання запиту користувача.
2. Створення ембедингу запиту.
3. Пошук найближчих векторів у FAISS.
4. Вибір трьох найбільш релевантних фрагментів.
5. Передавання знайденого контексту мовній моделі.

Перевірка пошуку виконується командою:

```cmd
python check_retrieval.py
```

### 4.5. Інтеграція RAG з асистентом

У бібліотечному асистенті використано два основні інструменти:

- `search_docs` — пошук інформації у документах бібліотеки;
- `book_info` — отримання інформації про конкретну книгу.

Інструмент `search_docs` дозволяє асистенту використовувати знайдені документи під час формування відповіді.

Для запитань про конкретні книги використовується `book_info`.

## 5. Експериментальні дослідження

### 5.1. Тестування RAG-пошуку

Для перевірки системи підготовлено **10 тестових запитів**:

- 4 прямі запитання;
- 4 перефразовані запитання;
- 2 запитання, відповіді на які відсутні у документах.

Результати:

| Тип перевірки | Кількість | Результат |
|---|---:|---:|
| Прямі запитання | 4 | 4/4 |
| Перефразовані запитання | 4 | 4/4 |
| Запитання без відповіді | 2 | 2/2 |
| **Усього** | **10** | **10/10** |

Для всіх восьми запитань із наявними відповідями правильний документ знайдено на першій позиції (TOP-1).

Обидва запитання без відповіді також пройшли перевірку.

### 5.2. Порівняння способів chunking

Для оцінювання впливу поділу документів проведено експеримент із шістьма конфігураціями.

Результати показали, що для п'яти конфігурацій правильний документ знаходився у TOP-1 для всіх восьми запитів із наявною відповіддю.

Для конфігурації `fixed_400` отримано 7 правильних результатів із 8.

| Конфігурації | Правильних TOP-1 | Точність |
|---|---:|---:|
| 5 досліджених конфігурацій | 8/8 | 100% |
| `fixed_400` | 7/8 | 87,5% |

Для подальшої роботи обрано `paragraphs_800`, оскільки ця конфігурація забезпечила правильне знаходження документів на тестовому наборі.

Детальні результати наведено у файлах:

### 5.3. Порівняння описів інструмента search_docs

Для визначення впливу опису інструмента на поведінку асистента проведено експеримент із трьома варіантами:

- **A** — перший варіант опису;
- **B** — другий варіант опису;
- **C** — третій варіант опису.

Кожен варіант перевірено на 10 запитах із трьома повтореннями.

Загальна кількість запусків:

**3 варіанти × 10 запитів × 3 повторення = 90 запусків.**

Результати експерименту:

| Показник | A | B | C |
|---|---:|---:|---:|
| Кількість запусків | 30 | 30 | 30 |
| Використання RAG | 15/30 | 27/30 | 24/30 |
| Частота використання RAG | 50% | 90% | 80% |
| Порожні відповіді | 6 | 0 | 3 |
| Прийнятні відповіді | 18/30 | 30/30 | 27/30 |
| Частка прийнятних відповідей | 60% | 100% | 90% |

| Середній час відповіді, с | 49,1 | 66,6 | 74,4 |

### 5.4. Аналіз результатів

За результатами експерименту встановлено:

**Варіант A**

- Найменша середня тривалість виконання — 49,1 с.
- RAG використовувався у 50% запусків.
- Зафіксовано 6 порожніх відповідей.
- Частка прийнятних відповідей — 60%.

**Варіант B**

- RAG використовувався у 90% запусків.
- Порожніх відповідей не зафіксовано.
- Отримано 30 прийнятних відповідей із 30.
- Середній час виконання — 66,6 с.

**Варіант C**

- RAG використовувався у 80% запусків.
- Зафіксовано 3 порожні відповіді.
- Частка прийнятних відповідей — 90%.
- Середній час виконання — 74,4 с.

Найкращим за часткою прийнятних відповідей виявився **варіант B**.

Його обрано для основної конфігурації бібліотечного асистента.

### 5.5. Оцінювання відповідей

Окремо проведено оцінювання відповідей асистента.

Для запитань із відомими відповідями застосовано автоматизовану перевірку за очікуваними ознаками у тексті.

Відповіді на запитання без інформації в документах перевірено окремо.

Тому показник 100% для варіанта B стосується лише використаного тестового набору та не означає гарантовану точність на будь-яких запитах.

Під час виконання лабораторної роботи №5 розроблено локального бібліотечного асистента з використанням технології RAG.

Для векторизації документів використано модель `bge-m3`, для пошуку — FAISS, а для генерації відповідей — локальну мовну модель `qwen25-4k` через Ollama.

Експериментально перевірено вплив способів поділу документів на якість пошуку. П'ять із шести конфігурацій забезпечили правильне знаходження документа в TOP-1 для всіх восьми тестових запитів із наявною відповіддю.

Порівняння трьох описів інструмента `search_docs` показало, що формулювання опису впливає на частоту використання RAG та якість відповідей.

Найкращий результат продемонстрував варіант B: 90% використання RAG і 100% прийнятних відповідей на використаному тестовому наборі.
