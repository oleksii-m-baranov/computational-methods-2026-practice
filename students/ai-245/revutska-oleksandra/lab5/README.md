# Лабораторна робота №5

## Локальний RAG-асистент бібліотеки

**Студентка:** Ревуцька Олександра  
**Група:** AI-245

## 1. Мета роботи

Реалізувати локального бібліотечного асистента з використанням технології RAG (Retrieval-Augmented Generation), дослідити вплив способів поділу документів на якість пошуку та порівняти ефективність різних описів інструмента `search_docs`.

## 2. Використані технології

- **Python** — реалізація програмної логіки.
- **Ollama** — локальний запуск мовної моделі.
- **qwen25-4k** — мовна модель асистента.
- **bge-m3** — створення векторних представлень тексту.
- **FAISS** — пошук релевантних фрагментів документів.
- **RAG** — генерація відповідей на основі знайденої інформації.

## 3. Опис реалізації

Розроблено бібліотечного асистента, який відповідає на запитання користувачів, використовуючи локальну базу документів.

Система містить 17 текстових документів. Вони розбиваються на фрагменти (chunks), перетворюються на вектори за допомогою `bge-m3` та індексуються у FAISS.

Під час запиту асистент знаходить релевантні фрагменти та використовує їх для формування відповіді.

Реалізовано два основні інструменти:

- `search_docs` — пошук інформації в документах бібліотеки.
- `book_info` — отримання інформації про конкретну книгу.

## 5. Запуск проєкту

Для роботи необхідно встановити Python, Ollama та потрібні Python-бібліотеки.

Завантаження моделей Ollama:

```cmd
ollama pull bge-m3
```

Мовна модель `qwen25-4k` має бути попередньо створена або налаштована в Ollama.

Створення векторного індексу:

```cmd
python build_index.py
```

Перевірка пошуку:

```cmd
python check_retrieval.py
```

Запуск тестових запитів:

```cmd
python check_cases.py
```

Порівняння описів інструмента:

```cmd
python compare_descriptions.py
```

Аналіз результатів:

```cmd
python analyze_descriptions.py
```

## 6. Проведені експерименти

### 6.1. Порівняння способів поділу документів

Досліджено 6 конфігурацій поділу тексту на фрагменти.

Для 5 конфігурацій отримано правильний результат TOP-1 у 8 із 8 тестових запитів.

Для конфігурації `fixed_400` результат становив 7 із 8.

Основною обрано конфігурацію:

- Chunking: `paragraphs_800`
- TOP_K: `3`
- Кількість фрагментів: `39`

### 6.2. Перевірка RAG-пошуку

Створено набір із 10 тестових запитів:

- 4 прямі запитання;
- 4 перефразовані запитання;
- 2 запитання без відповіді в документах.

Для 8 запитів, що мали відповіді в документах, правильний документ знайдено на першій позиції (TOP-1).

Обидва запитання без відповіді успішно пройшли перевірку.

### 6.3. Порівняння описів `search_docs`

Перевірено три варіанти опису інструмента: A, B і C.

Кожен варіант протестовано на 10 запитах із трьома повтореннями.

**Загальна кількість запусків — 90.**

| Показник | A | B | C |
|---|---:|---:|---:|
| Використання RAG | 50% | 90% | 80% |
| Прийнятні відповіді | 60% | 100% | 90% |
| Середня кількість токенів | 2599,9 | 4028,2 | 3664,6 |
| Середній час відповіді, с | 49,1 | 66,6 | 74,4 |

Найкращий результат на тестовому наборі показав **варіант B**.

Він забезпечив використання RAG у 90% запусків та 100% прийнятних відповідей на використаному наборі тестів.

Варіант B обрано для основної конфігурації асистента.

## 8. Висновки

У лабораторній роботі №5 реалізовано локального RAG-асистента бібліотеки на основі Ollama, FAISS та моделі ембедингів `bge-m3`.

Проведені експерименти показали, що спосіб поділу документів впливає на якість пошуку, а формулювання опису інструмента `search_docs` — на частоту його використання та якість відповідей асистента.

Найкращим серед трьох перевірених описів виявився варіант B, який забезпечив 100% прийнятних відповідей на тестовому наборі.

Отримані результати підтверджують ефективність використання RAG для пошуку інформації в локальних документах бібліотеки.
